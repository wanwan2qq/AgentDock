# 产品需求定稿

> 状态：已确认（2026-07）  
> 来源：产品讨论定稿；含后续澄清（不必 VS Code 壳；V1 小团队 Git）

## 产品定位

做一款**桌面端 Agent 友好知识库工作台**，面向个人与小团队。

它不是传统笔记软件，而是：

- **人**负责多格式阅读与审阅  
- **外接** Claude Code、OpenCode 等最先进编程助手负责生成与维护  
- **不自建**助手能力 / 大模型  

对标参考是 Obsidian，但要补上两点：

1. 不只擅长 Markdown——HTML、CSV、图片等 Agent 产物也是一等公民  
2. 原生适配编程助手的生成工作流（文件即真相源）

本仓库（AgentDock）以 NeverWrite fork 为起点，形态为独立桌面应用，**不要求**必须是 VS Code 壳。提及 VS Code 的初衷是：希望能使用最先进的编程助手能力，而不是自建一套。

## 核心目标

1. **高质量展示**多种 Agent 友好文件类型（人读体验一等公民）  
2. **高效生成与维护**知识库（借助外挂编程助手）  
3. **团队可共享**同一知识库（V1：小团队 Git）

## 功能需求

### 1. 多格式内容展示

| 类型 | 期望 |
|------|------|
| Markdown | 优质预览、链接/导航体验接近笔记工具 |
| HTML | 应用内可读（报告、仪表盘、交互页等 Agent 产物） |
| CSV | 表格化阅读，最好可简单编辑并回写 |
| 图片 | 内置预览（缩放等基础能力） |

这些格式与 Markdown 一样，都是知识库的**一等公民**，而不是附属附件。

### 2. 与编程助手协同

- 支持用 **Claude Code、OpenCode、Cursor** 等编程助手高效生成、更新知识库  
- 知识库以**本地文件**为真相源，便于 Agent 直接读写  
- 人可审阅 Agent 的写入结果（diff / review），而不是黑盒覆盖  
- 工作流低摩擦：打开知识库目录 → Agent 读写 → 人预览多格式产物  
- **不自建** Agent / 模型；复用本机已登录的主流助手

### 3. 团队知识库共享（V1）

- 多人可共享、同步同一套知识库  
- V1 采用 **Git**（clone / pull / commit / push / 冲突解决）  
- 变更可追溯；文件目录可移植，不锁死封闭专有格式  
- **不做**公司级 ACL、审计、Confluence 式权限；**不做** CRDT 实时共编

### 4. 产品形态

- 桌面应用  
- 不必绑定 VS Code；独立 Electron（本仓库）或其它能接上主流助手的形态均可  

## 非目标（当前明确不做）

- 纯云端 Notion 替代（除非未来评估共享方案）  
- 自建大模型 / 自研助手大脑  
- V1 完整 PKM 插件生态（图谱、日记等可作为后续）  
- V1 企业级权限与合规审计  
- V1 多人实时共编（CRDT）

## V1 成功标准

当团队成员使用本产品时，应能同时做到：

1. `git clone` 后打开同一知识库文件夹  
2. 人能流畅阅读 MD / HTML / CSV / 图片  
3. 用 Claude Code / OpenCode 生成或更新知识内容与产物  
4. 变更经 Git 可追溯、可合并；冲突可定位并处理  

## 建议的 V1 范围（执行边界）

1. 本地打开文件夹（即 Git repo）  
2. MD / HTML / CSV / 图片预览（CSV 可先只读表格）  
3. 对接本机 Claude Code、OpenCode（ACP 或终端）  
4. **不强制知识库目录模板**——目录结构、是否使用 `AGENTS.md` 等由使用者自行控制  
5. 基础 Git：status / diff / pull / commit / push；冲突给出文件列表  
6. 复用既有 Agent 变更 review（本仓库已有能力）  
7. （可选）仅提供最小 `.gitignore` 建议项，不强制写入固定目录骨架
