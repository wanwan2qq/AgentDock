# AgentDock 体验优化计划（串行验证）

> 原则：**影响面小、体感明显者优先**；不移植上游大块代码；**一项完成后你验证通过再做下一项**。  
> 对照：[上游机制影响](upstream-sync-checklist.md)、当前 `main` `6277060`  
> 工作方式：每项有「改什么 / 不改什么 / 你怎么验」。验不过就修，不跳项。

## 顺序总览

| 序号 | 项 | 体感 | 风险 | 状态 |
|------|----|------|------|------|
| 1 | 打开 vault 后的空聊天引导（中文 + 一键新建） | 高 | 低 | 已通过 |
| 2 | 开库遮罩：中文 + 诚实进度（去掉假 18%） | 高 | 低 | 已通过 |
| 3 | Git：提示忽略 `.neverwrite/`（确认后写入） | 中高 | 低 | 已跳过 |
| 4 | Tool 失败/拒绝原因显示在时间线 | 中高 | 低 | 已跳过 |
| 5 | ACP 断线中文说明 + 轻量「重试」 | 高 | 中 | 已通过（ACP 超时另议） |
| 6 | 长对话「滚到底」按钮更可靠 | 中 | 低–中 | 已通过 |

**明确不做（本轮）**：自定义 ACP 框架、聊天历史改存设备、sidecar 全局锁拆分、Codex 0.147、整页合上游 UI。

## 1. 空聊天引导（中文 CTA）

**为什么先做**：刚关掉「打开库自动建 3 个空聊」，现在侧栏是英文 `No chats yet for this vault.`，右侧 Agent 区也容易空着，不知道点哪。

**改什么**

- Agents 侧栏空态 → 中文：「这个知识库还没有对话」+ 按钮「新建对话」（走现有 New Agent / New chat）
- `+` / History 的 title、aria 中文化
- 右侧 Agent 空窗格（无 session）同样一句中文 + 同一按钮

**不改**：会话创建逻辑、`createDefaultSession`、分栏规则。

**你验证**

1. 打开一个没有聊天记录的 vault（或清掉侧栏会话）
2. 侧栏应看到中文空态和「新建对话」，点一下能开出 Cursor/OpenCode 等选择或直接新会话
3. 右侧 Agent 空窗格同样能新建，**不会**自动多出空聊天
4. 已有对话的库，列表行为不变

---

## 2. 开库遮罩诚实化

**为什么**：卡在 Scanning 时假进度条约 18% + 英文 Preparing index，像死机。死锁已修，文案仍会误导。

**改什么**

- 文案中文：`正在打开知识库…` / `正在扫描文件…`（`total=0` 时）
- `total=0` **不要**画固定 18% 条，改不确定动画或纯文字
- 有 `processed/total` 时再显示真实进度（若后端仍一次返回，至少不要假百分比）

**不改**：scan/index 实现、watcher 队列。

**你验证**

1. 打开团队镜像库 `af0692f7-…`
2. 遮罩应是中文；没有进度数字时**不应**看起来卡在 18%
3. 几秒内应进入工作区；Cancel 仍可用
4. 小库打开速度与现在相当

---

## 3. Git：忽略本地会话目录

**为什么**：历史写在 `vault/.neverwrite/sessions/`，团队 `git status` 容易脏。一键 ignore 比改存储位置安全。

**改什么**

- Git 面板或底栏：若已是 repo 且 `.gitignore` 未覆盖 `.neverwrite/`，显示「忽略本地会话目录」
- 点击后**确认**，再追加 `.neverwrite/`（不覆盖用户已有规则）

**不改**：历史落盘路径、自动静默改 gitignore。

**你验证**

1. 打开已 git 初始化、但未 ignore `.neverwrite` 的库
2. 能看到提示；确认后 `.gitignore` 多一行，status 里会话目录消失
3. 已 ignore 的库不重复提示
4. 未 init 的库仍只显示「初始化仓库」

---

## 4. Tool 失败原因可见

**为什么**：ACP 拒绝/失败常只显示 failed，知识库场景需要知道「为什么没改成」。

**改什么**

- 时间线 tool 卡片在 `failed` / `error` / 拒绝时展示 `summary` 或 ACP 返回的原因（已有字段优先，不做新协议）
- 过长截断，hover 看全文

**不改**：ActionLog / keep-reject 模型、权限弹窗流程。

**你验证**

1. 用 Cursor/OpenCode 触发一次被拒绝或失败的工具（如写只读文件）
2. 卡片上能看到原因，不只是 Failed
3. 成功工具卡片外观不变
4. 长原因不撑破布局

---

## 5. ACP 断线：中文 + 轻量重试

**为什么**：Cursor/OpenCode 空闲后会话挂死，现在只能重开。完整上游 #368 太大；先做「说清楚 + 再试一次」。

**改什么**

- 断线/runtime unavailable 错误 → 中文（如「助手连接已断开」）
- 该条错误旁按钮「重试连接」（resume 已有 session，不建新聊天）
- 不保证恢复未发出的半条 prompt（那是下一阶段）

**不改**：sidecar Mutex 拆分、自定义 ACP、完整 idle recovery 状态机。

**你验证**

1. 开 Cursor 对话后让 ACP 进程挂掉或空闲很久
2. 应出现中文断线说明，而不是一串英文 RPC
3. 点「重试连接」能回到可输入；失败则仍留在同一会话并提示
4. 正常发送不受影响

---

## 6. 长对话滚到底

**为什么**：长 transcript 时「跳到底部」有时不出现或点了不到底，体感差、改动相对局部。

**改什么**

- 新消息 / 打开已有会话时，未在底部则显示按钮
- 点击滚到真正底部（含 streaming 增高）

**不改**：虚拟列表架构（除非现有逻辑明显错了）。

**你验证**

1. 打开很长的历史对话，向上翻
2. 应出现滚到底；点击后停在最新一条
3. 正在 streaming 时点按钮，应跟上新输出
4. 已在底部时按钮消失
